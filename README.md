# 卫星遥测缺口修复（Telemetry Gap Repair）

卫星过站后会出现一段长度为 `n` 的连续遥测整体丢失。本服务用两种修复源
A、B，以首尾相接的半开区间 `[start, end)` 覆盖整个缺口 `[0, n)`，求最小
成本的完整分段方案。

## 代价定义

- 缺口位置编号为 `0 … n-1`。位置 `k` 上使用源 A / B 的逐位置代价分别为
  `costs[k].a`、`costs[k].b`，取值均为 `0 … 1_000_000` 的整数。
- 两种源各有一次性的**段启用费** `fee_a`、`fee_b`（同样为
  `0 … 1_000_000` 的整数）。**每启用一段就收一次**：即使相邻两段使用同一
  种源，后一段仍要重新支付启用费。
- 一段 `[i, j)` 只能选择一种源 `s`，其成本为

  ```
  fee[s] + Σ costs[k].s,  k ∈ [i, j)
  ```

- 方案由若干 `[start, end)` 段组成，满足
  `0 = start₀ < end₀ = start₁ < … < end_m = n`，每段长度
  `1 ≤ end - start ≤ L`。方案总成本是各段成本之和。

## 输入 / 输出

`POST /solve`，普通 JSON：

```json
{
  "n": 5,
  "L": 3,
  "fee_a": 10,
  "fee_b": 3,
  "costs": [
    {"a": 1, "b": 4},
    {"a": 2, "b": 3},
    {"a": 5, "b": 1},
    {"a": 1, "b": 4},
    {"a": 2, "b": 2}
  ],
  "objective": "default",
  "unavailable": {
    "a": [{"start": 1, "end": 3}],
    "b": []
  }
}
```

`objective` 为可选项，可省略，或取：

- `"default"`（默认）：最小成本后，继续按默认的段数、末段起点、末段来源顺序裁决；
- `"continuity"`：先保证最低总成本，再依次最小化相邻段的修复源切换次数、总段数、末段起点、末段来源。首段不计切换；这些键完全并列时，沿用前缀自身的同序裁决。

非法 `objective` 返回 **HTTP 422**，响应体只含标准 `detail`。

### 维护窗口（可选 `unavailable`）

`unavailable` 为可选项，省略、为 `null` 或两侧均为空列表时与旧版本**逐项兼容**。
可分别为 A、B 传入按缺口位置计的半开维护窗口 `[start, end)`：

- 每个窗口必须满足 `0 ≤ start < end ≤ n`；
- 同一来源的窗口按 `start` 严格递增，彼此**不得重叠也不得相接**
  （前一个窗口的 `end` 必须严格小于后一个的 `start`；A、B 两侧互不影响）；
- 任何使用某来源的完整分段 `[i, j)` 都不得与该来源的任一窗口相交
  （半开语义：分段恰好在窗口起点结束、或恰好在窗口终点开始是允许的）。

任何窗口非法都返回 **HTTP 422**，响应体只含 `detail`。若所有满足窗口约束的
分段链都无法完整覆盖 `[0, n)`（例如同一位置两源同时维护、或某源的可用区间
存在长于 `L` 的空洞），返回 **HTTP 409**：

```json
{"detail": "NO_FEASIBLE_REPAIR"}
```

409 响应不携带任何局部 `cost`、`segments` 或 `certainty`。窗口约束直接进入
递推的前驱范围、末段来源状态、反向最低成本与 certainty 合并，不存在“先求无
约束结果再裁剪”的路径。

返回：

```json
{
  "cost": 20,
  "segments": [
    {"start": 0, "end": 2, "source": "B"},
    {"start": 2, "end": 5, "source": "B"}
  ],
  "certainty": ["B_ONLY", "B_ONLY", "B_ONLY", "B_ONLY", "B_ONLY"]
}
```

`certainty` 长度为 `n`，逐位置（0 … n-1）报告该位置在**全部最低总成本方案**
中的来源确定性：

- `A_ONLY`：覆盖该位置的最优段只可能用 A；
- `B_ONLY`：只可能用 B；
- `EITHER`：存在两条总成本均为全局最小值的合法分段链，其中一条以 A 段
  覆盖该位置，另一条以 B 段覆盖它。

判定只依赖“成本是否等于全局最小值”，与段数、切换次数、末段起点 / 来源等
次级裁决无关——它们只是在最优方案集合中挑出一个，不会缩小集合。因此
`default`、省略 `objective` 与 `continuity` 对同一请求返回**完全相同**的
`certainty`；`cost`、`segments` 仍按各自 objective 的既有规则裁决，旧版本
的这两个字段逐值不变。输入校验失败时仍只返回含 `detail` 的 422，不泄露任何
局部 certainty。

约束：`1 ≤ n ≤ 200000`、`1 ≤ L ≤ 4096`；所有代价 / 启用费为
`0 … 1_000_000` 的整数。`len(costs)` 必须等于 `n`。任何长度不符、数值
越界、非法 `L` 或类型错误都返回 **HTTP 422**，响应体只含标准校验错误
`detail`，不返回成本，也不返回任何局部分段。

## 递推与唯一方案

令 `dp[j]` 为覆盖 `[0, j)` 的最优方案。对每个终点 `j`，在源
`s ∈ {A, B}` 与起点 `i ∈ [j-L, j-1]`（且 `i ≥ 0`）上取候选

```
(dp[i].成本 + fee[s] + Σ_{k=i}^{j-1} costs[k].s,
 dp[i].段数 + 1, i, s)
```

候选严格按四元组的字典序比较，依次为：

1. 累计成本（最小）
2. 段数（最少）
3. 前驱下标 `i`（最小）
4. 源（A < B）

因此递推唯一确定最优方案，不含任何随机或实现相关的平局处理。

### continuity 模式

`objective="continuity"` 在所有最低成本方案之间依次比较：

1. 相邻段来源切换次数（首段不计）；
2. 段数；
3. 末段起点；
4. 末段来源（A < B）；
5. 若仍并列，递归沿用前缀方案的同一套顺序。

例如 `n=3, L=1, fee_a=fee_b=0, costs=[(0,0),(1,0),(0,1)]` 时，最低成本为 0：
默认模式得到 `ABA`；continuity 模式在 `ABA`（两次切换）与 `BBA`（一次切换）之间选择
`BBA`。

## 算法

对固定源 `s`，候选值可改写为

```
(dp[i].成本 - prefix_s[i]) + prefix_s[j] + fee[s]
```

其中 `prefix_s[j]` 是源 `s` 在 `[0, j)` 上的逐位置代价前缀和；与 `i`
相关的部分只有 `dp[i].成本 - prefix_s[i]`，而可行起点 `i` 恰好构成滑动
窗口 `[j-L, j-1]`。

实现为每个源维护一个**单调双端队列**，队列元素的键为

```
(dp[i].成本 - prefix_s[i], dp[i].段数, i)
```

- 窗口左沿滑出的队首直接淘汰；
- 入队时从队尾弹出键严格更大的元素（键相同则保留更小下标，以满足“前驱
  下标更小优先”的平局规则）。

每个下标每源入队 / 出队至多一次，整体复杂度 **O(n) 时间、O(n) 空间**
（优于 O(n log n) 要求），不逐终点枚举 `L` 个起点，也不调用任何优化求解
器。结果由前驱指针回溯重建，每段都可按上述递推独立重算并精确复现报告的
最优成本。

`continuity` 模式为“末段来源 A / B”分别保存前缀状态。每个新来源只从对应
末段来源的状态窗口转移；另外使用无来源哨兵仅生成首段，首段不增加切换数。
哨兵不会写入 A / B 状态窗口，回溯也只引用 continuity 自己的状态，因此不会
事后改写默认模式中已淘汰的前缀。每个 `(前一来源, 新来源)` 组合维护一个滑动
窗口；窗口键在最低成本外包含切换数和段数，跨窗口比较再使用末段起点、末段
来源和前缀完整裁决键。默认模式仍走独立的原有递推，比较键与结果保持不变。
两种模式在 `n=200000, L=4096` 下均为 **O(n) 时间、O(n) 空间**。

## 维护窗口如何进入递推

对每个来源，所有合法分段的两端必须落在同一个“可用块”内（块由该源互不相交
的窗口隔出）。预处理各用一次线性扫描得到两个边界数组：

- `floor_s[j]`：以 `j` 为终点的源 `s` 段，其起点必须满足
  `i ≥ max(j-L, floor_s[j])`。`j` 在窗口 `[s,e)` 严格内部时取 `e`（窗口内不
  可能成为段终点，该下界会让所有 `i<j` 过期）；窗口之后的块取窗口的 `e`；
  `j == s` 仍属前一块（段可终于窗口起点）。
- `ceil_s[i]`：以 `i` 为起点的源 `s` 段，其后继必须满足
  `j ≤ min(i+L, ceil_s[i])`，规则对称（窗口内取窗口起点，之后取下一个窗口
  起点，末尾块为 `n`）。

于是默认 DP、continuity DP 的每个来源窗口只需把过期条件从 `i < j-L` 改为
`i < max(j-L, floor_s[j])`；后缀最低成本 `g` 的反向窗口同理使用 `ceil_s`；
certainty 的可行性判据只在“前缀可达、后缀可达且通过窗口过期检查”的 `(i,j,s)`
上成立。不可达状态保持无穷大且**从不入队**，因此不会污染单调队列，也不产生
任何需要裁剪的无约束方案。两个边界数组只对窗口与位置各扫一遍，不展开位置与
窗口的笛卡尔积，全程仍为 **O(n) 时间、O(n) 空间**。

## certainty 的计算

令 `f[i]` 为覆盖 `[0, i)` 的最小成本（不区分末段来源），`g[j]` 为覆盖
`[j, n)` 的最小成本。一段源 `s` 的 `[i, j)` 能出现在某条全局最优方案中，
当且仅当

```
f[i] + fee[s] + P_s[j] - P_s[i] + g[j] == f[n]
```

其中 `P_s` 是源 `s` 的逐位置代价前缀和。充分性来自把**任意**最优 `[0,i)`
前缀、该段、**任意**最优 `[j,n)` 后缀直接拼接：它合法且总成本恰为
`f[n]`；必要性则因任何含此段的方案成本都不低于该和、而全局最小为 `f[n]`。

对固定终点 `j` 与源 `s`，可行起点范围 `[max(j-L, floor_s[j]), j-1]` 上只需
判断 `h_s(i) = f[i] - P_s[i]` 的窗口最小值是否等于目标值
`f[n] - g[j] - fee[s] - P_s[j]`（其中 `g` 的递推同样受 `ceil_s` 约束）。用
与主递推同构的单调双端队列维护 `h_s(i)`（等值保留更小下标），取到最小值的
最小起点 `i_min` 的单段 `[i_min, j)` 已经覆盖所有最优起点区间 `[i, j)` 的并
集 `[i_min, j)`。将每个 `(j, s)` 的这一区间写入按源区分的差分数组，最后线性
扫描即可得到逐位置的来源并集。

- 不枚举任何完整分段（每个 `(j, s)` 只贡献至多一个区间，总共 O(n) 个），
  也不只重放胜出前驱——那会漏掉其他同样最优的前驱；
- `f` 与 `g` 各是一趟滑动窗口最小值 DP（后缀 DP 的窗口沿下标递减方向滑
  动，队首淘汰 `k > j+L` 的后继），含 certainty 合并全程 **O(n) 时间、
  O(n) 空间**，`n=200000, L=4096` 下与原求解器同量级。

## 运行

要求 Python 3.12（或用 Docker）。

本地：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Docker Compose：

```bash
docker compose up --build          # 宿主端口默认 8000
API_PORT=9000 docker compose up    # 用 API_PORT 覆盖宿主端口
```

容器以非 root 用户 `appuser`（uid 10001）运行。

## 一次性验收

`verify` 是一次性服务，运行 pytest 后退出：

```bash
docker compose run --rm verify
```

## 测试

`tests/test_solver.py` 包含：

- `n ≤ 8` 的小规模预言机会枚举全部合法切分与 A/B 来源，并分别核对
  `default`、`continuity` 的完整递归裁决；
- 独立的 certainty 预言机枚举**全部**合法分段及来源、只保留总成本等于
  全局最小值的方案，核对逐位置来源并集；`n=3、L=2、费用全 0、
  costs=[(0,5),(0,0),(5,0)]` 锁定为 `[A_ONLY, EITHER, B_ONLY]`，两个
  objective 完全一致；另有 O(nL) 的朴素前缀 / 后缀切分预言机在
  `n=200000, L=3` 及随机中小规模上对拍；
- `n = 3, L = 1`、费用全零、`costs=[(0,0),(1,0),(0,1)]` 锁定默认 `ABA`、
  continuity `BBA`；`cost`、`segments` 保持旧版本逐项回归；
- 随机小规模 / 中规模对拍，以及 `n = 200000`、`L = 4096` 的两种模式最大
  规模用例（含 certainty 的 O(n) 时限）；continuity 与独立的惰性删除堆
  参考实现逐段比对，并校验时限；
- `n = 200000`、`L = 3` 时默认模式与朴素 O(nL) 递推对拍；
- 对每个返回方案按代价定义直接重放，断言恰好等于返回成本，且分段首尾相
  接、长度合法；
- 省略 `objective` 与显式 `"default"` 的 `cost`、`segments` 完全一致；
- 长度不符、越界、非法 `L`、非法 `objective`、错误类型、缺字段均返回
  422 且响应体只含标准 `detail`；
- `tests/test_unavailable.py` 用枚举全部合法分段与来源的短序列预言机（过滤
  掉与维护窗口相交的段）交叉核对两种 objective、certainty 并集与不可行裁决；
  覆盖窗口端点（0、窗口起点/终点、n）、单源全失效、两源同时失效（409 且仅
  含 `detail`）、同源相接/重叠/乱序区间拒绝（422 仅含 `detail`）、省略/空
  `unavailable` 的旧请求逐项回归，以及带密集窗口的 `n=200000` 线性时限用例。
